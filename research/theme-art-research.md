# F1 LapLab: experimental direction and six-way differentiation

Research date: 7 October 2026. Scope: bounded web-only visual reference research for the sixth direction; no shared browser use, application edits or publishing.

## Sixth direction: Lap Score

Make a lap an explorable graphic score. The recorded/modelled signal is the visual artwork: acceleration arches, brake events, gear steps, sector boundaries and deltas produce a unique composition for each circuit and scenario. This makes a genuinely unconventional interface without replacing the lab with an arbitrary animation.

Use an asymmetric, almost poster-sized instrument surface: a narrow vertical identity/index strip; an oversized lap figure and track name above a full-width distance score; a large companion circuit diagram at one side; and a horizontal control rack below. The score is the visual and interaction center. A thin moving playhead extends across the chart bands, while the synchronized circuit shows where it is. Keep the circuit's simulation, hover and scrub working exactly as in the other directions.

**Visual proposal:** vivid signal-yellow canvas (#E9F042), ink-black text (#15160F), near-white data surfaces (#F6F6EB), and restrained electric cobalt (#2852DC) for reference B. Large grotesk typography can feel physical and graphic: a 72–104 px lap number at desktop, 36–48 px on mobile; all values/axes remain 12–14 px monospaced/tabular. Existing IBM Plex Sans/Mono can work; use weight/scale and composition rather than adding an unreadable display font. Solid color fields, square corners, cropped oversized section indices in the margin, long thin rules. Avoid texture over plots and text. Gain/loss uses signed labels plus distinguishable line style; saturated red/green need not carry the meaning.

**Navigation:** use four clear text tabs in a persistent lower tool strip: Run / Signals / Compare / Evidence. Keep these conventional buttons even if surrounding art direction is bold. Conditions, Vehicle and Driver can expand upward as aligned tool trays; preserve all existing inputs, ranges and validation. The initial view must already show the lap result, uncertainty, track and chart, with no intro animation or gate. On touch screens the strip remains compact and the trays open inline, without covering every chart.

**Charts:** speed is a large line with a fine grid and ticked distance axis; throttle and brake are separate filled signal bands; gear and DRS/ERS are stepped bands. Add a measured sector/corner stripe above them. The chart is an actual telemetry plot, not a spectrogram pretending to measure new data. Use a shared cursor and a stable numerical cursor legend. Comparison overlays stay labeled A/B and use consistent scales. A compact selected-corner note can attach to the playhead, reporting actual modeled values and the existing causal explanation. Do not let oversized typography obscure the data.

**Motion:** the only persistent motion is the simulated car, synchronized chart playhead and changing current readouts. Brief tray transitions can be 150–200 ms and respect reduced-motion settings. No wobbling chart, ambient particles or audio that suggests telemetry which was never supplied. The composed page should remain compelling while paused.

## Primary reference research

These are sources for interaction/design principles, not sources for the lap physics. The principles below are interpretation from creator documentation; pixel-level visual conclusions are unverified in this web-only pass.

- **Pattern Radio: Whale Songs — Google and NOAA.** Google's project article describes one large zoomable spectrogram ranging from individual sounds to months of recordings, annotation/highlight aids, deep links and guided tours. Transfer: the data is the main canvas, navigation means moving to meaningful parts of it, annotations teach without replacing exploration. Adapt to an existing distance-based lap score; do not add an invented frequency metric. [Creator article](https://blog.google/innovation-and-ai/products/pattern-radio-whale-songs/) · [Live experience](https://patternradio.withgoogle.com/) · [Official zoom example](https://storage.googleapis.com/gweb-uniblog-publish-prod/original_images/zoom_in.gif) · [Official pattern highlight example](https://storage.googleapis.com/gweb-uniblog-publish-prod/original_images/similar_sounds.gif).

- **Dear Data — Giorgia Lupi and Stefanie Posavec.** The creators describe weekly measured data transformed into individual postcards, each paired with a detailed key to decipher the marks. Transfer: a circuit/scenario produces its own signature; a precise legend gives experimental marks an honest meaning. Retain numerical axes and source/estimate labels; do not copy the handwriting or personal documentary purpose. [Creators' project](https://www.dear-data.com/theproject) · [Pentagram project](https://www.pentagram.com/work/dear-data).

- **Radio Garden — Moniker and Studio Puckey.** The co-creator page describes exploring live radio by place around the globe, with alternative History/Jingles/Stories sections. Transfer: a spatial object can itself be navigation, while ordinary section controls still provide escape paths and explanation. LapLab's track can select an actual corner and synchronize its evidence; keep keyboard/touch equivalents. [Co-creator project](https://studiomoniker.com/projects/radio-garden) · [Experience](https://radio.garden/).

- **Chrome Music Lab — Google Creative Lab.** The official page and repository characterize a family of direct, hands-on browser experiments. Transfer: present an understandable instrument immediately and let the input produce a visible signal. This supports a compact bottom control rack and explicit selected readout. [Official site](https://musiclab.chromeexperiments.com/Spectrogram/) · [Creator repository](https://github.com/googlecreativelab/chrome-music-lab).

**Access limitation:** Pattern Radio's live page returned no extractable text; the Google article was readable but its linked GIFs could not be fetched by the web tool. Dear Data and Moniker project descriptions were readable; linked images did not yield inspectable rendered visuals. Chrome Music Lab returned a browser-technology fallback in web extraction. Wind Map creator URLs timed out/failed and were excluded from the primary direction. No live browser-rendered screenshot was inspected during this pass. Earlier engineering references are documented in `work/visual-research.md`; those were actually visually inspected previously.

## Six-way differentiation matrix

The key is changing spatial organization and visual hierarchy. Color tokens alone cannot satisfy this brief.

| Direction | First-view structure | Navigation and input placement | Typography and rhythm | Telemetry presentation | Distinctive behavior of the shell |
|---|---|---|---|---|---|
| Apple-inspired | Spacious centered workspace; large result above a clean circuit; a small floating-looking readout, with two-column detail below | Compact top segmented navigation; conditions in a right inspector or orderly disclosure sheet | Calm sans, generous white space, large but restrained values; white/cool-neutral surfaces | Fine smooth speed line in a broad white plot; secondary bands folded behind explicit channel tabs | Gentle transitions and deliberate focus; a selected panel becomes the clear working object |
| Netflix-inspired | Dark cinematic circuit stage occupying the top; scenario/comparison shelves below; strong full-width result placement | Compact top navigation; controls in a left overlay drawer; saved scenarios as horizontal rails | Bold compact sans, large title/result, dark blocks, high contrast, red primary action | Expandable full-width “analysis” stage beneath the main circuit; reference A/B strip above traces | Primary Run/Replay action prominent; shelves make scenarios easy to browse while core simulation stays accessible |
| Engineering lab | Dense simultaneous docked panes: settings left, circuit/readouts center, analysis right, charts below | Persistent left configuration rail and top workbook-style tabs | Monospace values, 11–14 px tables and labels, neutral graphite, precise rules | Several shared-distance trace bands visible together, compact legends and cursor values | Minimum shell motion; all useful data available in one working view |
| Editorial motorsport | Broad masthead followed by an annotated circuit figure; lap estimate as a large editorial number; asymmetrical evidence columns | Section index or compact masthead links; inputs integrated in an experiment column | Large editorial heading plus restrained serif prose; warm neutral page and ink lines; captions and pullout data | Plots as numbered figures with units/captions; corner findings alongside, while synchronized cursor stays active | Clear reading order: select, run, examine, understand; navigation feels like an analytical publication |
| Futuristic race control | Circuit dominates as a command-center map; status/readout modules arranged at edges; telemetry in a bottom command deck | Persistent compact command bar; inputs in edge panels or deployable side racks | Condensed technical headings, tabular data, black/blue-black base with cyan functional signals | Dark trace grids and thin state strips, aligned to a large central crosshair/readout | The current simulation state is continuously legible; restrained framing/HUD signals organize, rather than decorate |
| Experimental / Lap Score | Full-width lap score as the main canvas; oversized result and vertical identity strip; circuit as companion specimen | Lower text navigation and horizontal input tool rack; upward/in-line trays | Oversized grotesk plus precise mono; signal-yellow, ink and near-white fields; square edges and asymmetric scale | Telemetry becomes the graphic composition, retaining true axes, stepped states, legends and cursor synchronization | One continuous playhead ties the page together; the paused composition remains useful and distinctive |

## Shared behavior that must survive every direction

Reuse the same simulation result and component logic for all six shells. Theme switching must preserve every selected input, simulation, selected distance, playback state/rate, reference lap, saved scenario and comparison. Do not remount the entire app or duplicate engines to change layout. Keep all controls available; alternate placement is fine, silent loss of function is not.

All directions still need the same uncertainty, empirical/estimated/assumed distinctions, validation samples, errors/loading states, accessible labels, source links and corner explanations. A visual direction cannot make modeled data appear observed. Keep responsive DOM/read order sensible and maintain keyboard focus when trays/panels close. Verify the same changed-input scenario, playback/scrub, comparison, saving/loading and sources across every shell.

The requested six directions should be selectable live, with short descriptive names and a clear current selection. A shared theme chooser can remain consistent so the user can compare them; each destination must visibly change layout, hierarchy and chart treatment rather than only surface color.
